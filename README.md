# Истина · Анализ продаж

Еженедельный отчёт по продажам кухни и бара. Один файл, открывается двойным
кликом — ни установки, ни интернета, ни сервера.

## Начать

Скачайте **`отчет.html`** и откройте в браузере. История за 2026 год
(36 недель) уже внутри, отчёт открывается сразу с цифрами.

## Раз в неделю

1. Вкладка **«Данные»**.
2. Перетащите обе выгрузки — по кухне и по бару. Период и раздел определяются
   по шапке файла, можно бросать сразу несколько недель.
3. Дашборд и «Категории» пересчитаются сами.
4. Там же, внизу, нажмите **«Экспортировать базу»** и положите файл в облако.

Четвёртый шаг — не формальность. База лежит в браузере на этом компьютере:
на другом её нет, чистка истории браузера её удаляет, при смене ноутбука она
не переедет. Файл базы — единственный способ перенести работу и поделиться ею
с коллегами (у них: «Импортировать базу»).

## Что на экранах

**Дашборд** — показатели за период с сравнением к предыдущему такой же длины:
отдельно общее по предприятию, по кухне и по бару. Ниже доли кухни и бара по
выручке, прибыли и количеству, динамика по неделям, сравнение кухни с баром и
топ позиций по количеству и по прибыли.

**Категории** — та же таблица, что вы вели руками: строки категорий и позиций,
колонки недель, справа итог. Категория разворачивается в позиции.

**Данные** — загрузка выгрузок, журнал загрузки, список загруженных недель с
возможностью удалить, банкеты вручную, справочник групп бара, экспорт и импорт
базы.

Фильтры сверху: период (включая «Последняя неделя», «Предыдущая неделя» и свой
диапазон), раздел, группа бара, категории.

## Группы бара

АЛКОГОЛЬ, БОКАЛЫ, КОКТЕЙЛИ, БУТЫЛКИ, Б/А в выгрузке отсутствуют — они задаются
на вкладке «Данные». Состав перенесён из вашего старого отчёта; изменение
применяется сразу ко всем неделям, включая прошлые. По группе можно
фильтровать весь дашборд.

## Что отчёт делает с данными сам

**Наценка не усредняется по позициям** — считается от сумм периода:
прибыль ÷ себестоимость. Иначе цифра уезжает.

**Строки, которых нет в выгрузке.** Иногда система печатает «Итого» по
категории, но не все строки под ним. Разница сохраняется позицией
«(без детализации)» — без этого бар за 17.08 терял 52 штуки и 27 тыс. ₽.

**Переименования.** Позиции сопоставляются по схожести названий: если блюдо
переименовали, история не разрывается. Порог задаётся в настройках компонента
(по умолчанию 90%).

**Неполные недели.** Если за неделю загружен только один раздел, отчёт
предупреждает и считает по тому, что есть, а не нулём.

**Повторная загрузка недели** заменяет данные, а не удваивает.

## Осталось решить

1. **Бар в истории, похоже, сдвинут на неделю.** В старом отчёте столбец
   «24-30» по бару содержит 667 штук — ровно столько, сколько в выгрузке за
   17–23 августа. По кухне сдвига нет. Если это так, историю нужно
   переимпортировать со сдвигом; либо загрузите настоящие выгрузки поверх.
2. **Позиции с наценкой −100%** (комплименты, списания) входят в общие цифры
   и тянут наценку вниз. Выносить отдельно?
3. **Столбец «срез»** в старом отчёте везде пустой — что в него должно попадать?
4. **За неделю 10–16.08 нет выгрузки по бару** — потерялась или не делали?

## Для тех, кто правит код

`отчет.html` собирается из исходников, руками его не редактируют.

```bash
node build.mjs    # собрать отчет.html
node test.mjs     # проверки (нужен: npm i jsdom)
```

| Файл | Что внутри |
|---|---|
| `src/template.html` | разметка экранов |
| `src/app.js` | вся логика: разбор выгрузок, база, агрегации, экраны |
| `src/xlsxread.js` | чтение .xlsx: распаковка ZIP и разбор XML, без библиотек |
| `src/xlsx-shim.js` | обёртка с интерфейсом SheetJS поверх своего читателя |
| `src/boot.js` | передача шаблона рантайму текстом (см. ниже) |
| `src/props.txt` | настройки компонента |
| `vendor/` | React 18 и рантайм Claude Design |
| `data/history.json` | история 2026 года из ручного отчёта |
| `build.mjs`, `test.mjs` | сборка и проверки |

Три места, где пришлось отойти от исходного документа дизайна:

- **React встроен в файл.** Рантайм грузил его с CDN — теперь берёт готовый.
- **Чтение Excel своё.** Вместо библиотеки с CDN — собственная распаковка,
  обёрнутая в тот же интерфейс `XLSX.read` / `sheet_to_json`.
- **Шаблон передаётся рантайму текстом** (`src/boot.js`). HTML-парсер
  выбрасывает `<sc-for>` внутри `<select>` — там разрешены только `<option>`,
  из-за чего выпадающие списки оставались пустыми.

Ещё база готовится в конструкторе, а не в `componentDidMount`: списки в
шаблоне собираются при первом рендере и потом не пересобираются.
